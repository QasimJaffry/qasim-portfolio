## The Problem

Freelancers keep leads, proposals and deals across spreadsheets, email threads and CRMs they never fully set up. Most CRMs are built for sales teams, not for one person running their own clients, and they leave all the tracking to you.

## What I Built

Dealflow AI is a personal project: a CRM for freelancers, with a **Next.js** web app and an **Expo** mobile app on one **Supabase** backend. The code is on [GitHub](https://github.com/QasimJaffry/DealFlow).

- **Pipeline.** Clients, deals (kanban and list), tasks, an activity timeline and a dashboard.
- **Deal workspace.** Notes, reminders and file uploads to Supabase Storage.
- **AI help.** Summarise a deal, pull out next actions, draft a follow-up or transcribe audio. Suggestions go through an **approve, then create tasks** step, so nothing changes in the pipeline without you.
- **Server-only AI routes.** Model calls run in `/api/ai/*` on the server, so keys stay off the client.
- **Typed monorepo.** `@dealflow/shared` and `@dealflow/ui` keep the web and mobile apps on the same types and components.

## Key Challenges

**One data model, two clients, no custom API.** Next.js and Expo both read the same Supabase data through shared typed packages instead of a separate API layer.

**AI inside the workspace.** AI calls had to be quick enough to feel like part of the deal page rather than a separate chatbot tab, and they never write to the pipeline without approval.

## Results

In development. The pipeline screens and the AI flow work. Email and calendar sync, push notifications and an offline write queue are still to come.

## Stack Decisions

Supabase so both clients get typed access to the same Postgres data without maintaining an API. Server-only AI routes keep keys off the client. OpenRouter, OpenAI and Groq cover text and transcription, so the provider can change without touching the product.
